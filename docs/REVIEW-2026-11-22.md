# Code and docs review, 2026-11-22

On Jeel's word after A34's real-phone calls ("make sure each thing is documented and not any single low quality code"), every area of the repo was read against its docs: six reviews, one per area - Seri (`backend/src/ai/`), browser and automated calls, leads and the SMS flow, the agent and admin API, the frontend, and the scripts, infrastructure and repo-wide docs. Each finding below was reported with the line it is on; the ones marked **checked** were then read again in the code before being listed here. Nothing was changed by the review itself.

This file is the tracker: each finding is fixed on its own branch into `dev`, with its tests and its doc, and its status here changes in the same commit. A finding found not to hold when it is fixed is marked so, with why.

Kinds: **bug** - the code does the wrong thing; **privacy** - something is written where it must not be; **doc** - a doc says what the code does not; **quality** - dead code, copies, stale comments, missing tests. Sizes of harm: **high** before launch, **medium** soon, **low** when touched.

## Decisions needed (Jeel)

| # | Question | Why it matters |

| D1 | Does the client send other campaigns from the same EZ Texting account? | A reply is matched to a lead by its phone number alone (`api/webhooks.ts`): a lead who answers another of the client's campaigns is read as an answer to our question - scored, asked again, put in review, or a block lifted on "YES". If yes, only replies to our own texts (`in_reply_to_ezt_id`) should run the flow |
