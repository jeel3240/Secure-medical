# Code and docs review, 2026-11-22

On Jeel's word after A34's real-phone calls ("make sure each thing is documented and not any single low quality code"), every area of the repo was read against its docs: six reviews, one per area - Seri (`backend/src/ai/`), browser and automated calls, leads and the SMS flow, the agent and admin API, the frontend, and the scripts, infrastructure and repo-wide docs. Each finding was reported with the line it is on; those marked *(checked)* were read again in the code before being listed. Nothing was changed by the review itself.

Each finding was fixed on its own branch into `dev`, with its tests and its doc, its status here changed in the same commit - and a finding found not to hold when it was fixed would have been marked so, with why. The ids say what each is: **D**, a decision for Jeel; **H**, high - to fix before launch; **M**, medium - soon; **R**, a doc that said what the code does not; **Q**, code quality - dead code, copies, stale comments, missing tests. Each finding's kind is its first word - a **bug** (the code does the wrong thing), **privacy** (something written where it must not be), **doc** or **quality** - and its fix follows it.

Found fine: every route has its guards; the JWT, cookie and bcrypt match `AUTH.md`; no user input reaches SQL as text; every Twilio route checks the signature and every webhook is safe to repeat; the claim race is one statement with its activity row; migrations 001-024 match `SCHEMA.md`; every `ai_*` and call log line is in `LOGGING.md` and none carries words said; every word of Seri's passes the sentence check; the poller's checkpoint moves only after a whole cycle; one open conversation per lead is held by an index; the frontend's types match the backend's responses; every path in `CLAUDE.md` §4 exists; every doc was in `docs/README.md`'s table; dev scripts refuse production and ring only test numbers; `npx tsc --noEmit` is clean for `src/` in both apps.
